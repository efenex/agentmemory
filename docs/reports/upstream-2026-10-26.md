## Reported failures and findings

The reported 379-second cold start, 180-second list timeouts, 1.56-GB RSS and 10.8k/43.9k compression failures are operator evidence, not measurements made in this run.

| Symptom | Findings and action |
| --- | --- |
| Cold ready takes 379 s | Upstream moves embedding recovery into a bounded background backlog and improves checkpointing. Startup still awaits stored vectors and keyword scans. Its default worker wait is 300 s, shorter than the reported cold start; propose 600 s below. Telemetry previously began full-store scans before keyword rebuild completed; it now starts after readiness. No measured new cold-start time is claimed. |
| BM25 backfill / supersession list timeouts | `StateKV.list()` still invokes unpaginated `state::list`. Keyword rebuild lists memories and sessions, then reads observation scopes in batches of ten. Supersession uses indexed candidates when ready, but retains a full-memory fallback when the index is unavailable or fails. These paths remain susceptible to large-scope transport/storage cost. Telemetry no longer duplicates startup scans, overlaps refreshes, or lists heavy graph records. Pruning or a separately designed storage pagination/sharding migration remains necessary if timeouts persist. |
| `termCount` undefined and keyword-only fallback | Old split BM25 snapshots can contain inverted postings without matching document entries. Upstream content rebuild avoids restoring that snapshot, but scoring still assumed consistency. Regression tests reproduced exceptions in exact and prefix lookup after the merge. Search now ignores orphan/invalid-length entries, clamps stale document frequency, and handles zero stored aggregate length without NaN scores. |
| `memory_critical_98%`, RSS 1.56 GB | Old health code divided `heapUsed` by currently allocated `heapTotal`, not the V8 maximum. This does not establish heap-ceiling exhaustion. Upstream `8deb131` changes the denominator to `heap_size_limit`. The repository's local Compose profile has a **5-GiB total container limit**, shared by Node, engine and workers, and no extra swap. The heap proposal below is 2 GiB, subject to actual runtime headroom; a 4-GiB Node heap would leave little room for the other processes. |
| `mem::compress` failures | `d9a20da` retains failure state/raw evidence and adds scoped status/retry endpoints; durable capture also improves recovery. The aggregate failure count alone cannot distinguish provider errors, malformed output, timeouts or lost source data. Existing records with `source_unavailable` cannot be repaired by retry alone. Kept the fork's thinking-disable option and ensured it reaches workers. No mass retry was attempted. |

Additional fixes retain exact int8 checkpoint bytes instead of repeatedly normalizing them, stream legacy embedding shards instead of first collecting every encoded row, reject partial shard recovery as a complete checkpoint, and fix the legacy embedding backfill helper to use the public vector iterator. Old fork snapshots remain available after conversion; this intentionally does not reclaim their disk space automatically.

Graph compaction now accepts a validated REST `dryRun` boolean. Preview does not mutate provenance or record a successful-compaction audit entry. Actual compaction still trims historical provenance to the existing bound, so preview counts and backup/recovery requirements matter.
